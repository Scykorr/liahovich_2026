# Техническое задание для Cursor: Django-приложение кластерного анализа

## Цель

Создай production-ready веб-приложение на Django для воспроизводимого кластерного анализа агрегированных результатов голосования по УИК. Не делай «демо-макет»: реализуй рабочий импорт, валидацию, фоновые расчёты, хранение результатов, тесты и документацию. Не добавляй автоматических утверждений о нарушениях; интерфейс описывает только статистические профили.

## Стек и ограничения

- Python 3.12, Django 5.2 LTS, PostgreSQL 16+, Redis, Celery 5.6.
- pandas, numpy, scipy, scikit-learn, statsmodels, openpyxl, Plotly.
- Django templates + Bootstrap 5 + HTMX; без обязательного Node.js.
- Docker Compose для `web`, `worker`, `redis`, `db`.
- Конфигурация только через environment variables; приложить `.env.example` без секретов.
- Типизация нового кода, Ruff, pytest, pytest-django, coverage.
- Интерфейс и сообщения пользователю — на русском языке.

## Архитектура

Создай приложения: `accounts`, `projects`, `datasets`, `validation`, `analytics`, `reports`, `audit`. Статистические функции вынеси в `analytics_core`, который не импортирует ORM. Сервисы Django вызывают ядро и сохраняют результаты. Не помещай бизнес-логику во views, templates или signals.

## Роли и доступ

- `ADMIN`: пользователи, справочники, системный аудит.
- `ANALYST`: проекты, версии данных, запуски, публикация отчётов.
- `VIEWER`: только разрешённые опубликованные результаты.
- Используй object-level проверки членства в проекте. Для чужого объекта возвращай 404 или 403 по единой политике.
- Записывай создание, изменение прав, загрузку, запуск, публикацию, экспорт и удаление.

## Модели

Реализуй `Project`, `ProjectMembership`, `Dataset`, `ColumnMapping`, `PrecinctRecord`, `ValidationIssue`, `AnalysisRun`, `FeatureDefinition`, `ModelCandidate`, `ClusterAssignment`, `ClusterProfile`, `Artifact`, `AuditEvent`. Для версионируемых сущностей добавь UUID, timestamps и автора. `Dataset` после запуска неизменяем; исправление создаёт новую версию. Сохраняй SHA-256 файла и JSON-схему. `AnalysisRun` хранит полный JSON-конфиг, seed, версии библиотек и статус: `draft/queued/running/succeeded/failed/cancelled`.

## Импорт

Поддержи `.csv` и `.xlsx`. Ограничение размера задаётся переменной окружения. Загруженный файл сначала попадает в карантинное хранилище, проходит проверку расширения, MIME, размера и безопасного имени. Для CSV определи кодировку UTF-8/UTF-8-SIG и разделитель, но дай пользователю исправить выбор.

Обязательные канонические поля: `territory_code`, `precinct_code`, `registered_voters`, `ballots_in_boxes`, `outside_ballots`, `valid_ballots`, `invalid_ballots`, минимум два `candidate_*`. Коды считывай строками. Сделай экран сопоставления колонок и предпросмотр 20 строк.

Валидации: обязательность, уникальность пары кодов, целые неотрицательные счётчики, ненулевые знаменатели, `valid_ballots + invalid_ballots == ballots_in_boxes`, сумма `candidate_* == valid_ballots`, значения частей не больше соответствующих итогов. Ошибки блокируют запуск, предупреждения требуют подтверждения. Предоставь CSV отчёта ошибок.

## Формулы

Рассчитывай:

- `turnout = 100 * ballots_in_boxes / registered_voters`;
- `outside = 100 * outside_ballots / ballots_in_boxes`;
- `invalid = 100 * invalid_ballots / ballots_in_boxes`;
- `candidate_share = 100 * candidate_votes / valid_ballots`.

Обрабатывай деление на ноль явной ошибкой. Не доверяй импортированным процентам. Производные `opposition_sum` и `leader_margin` используй для интерпретации, если они алгебраически зависят от признаков модели.

## Аналитический конвейер

1. Выбор правил пропусков и выбросов; по умолчанию ошибки строк блокируют расчёт, выбросы только помечаются.
2. Удаление признаков с менее чем 3 уникальными значениями или практически нулевой дисперсией.
3. Корреляционный экран по `abs(Pearson r) >= 0.80`; решение и причина сохраняются.
4. Итеративный VIF с порогом 5 по умолчанию.
5. Перебор комбинаций признаков размером 2–4 и `k=2..6`.
6. Pipeline `StandardScaler` или `RobustScaler` + `KMeans(init="k-means++", n_init>=20, random_state=seed)`.
7. Рассчитать Silhouette, Calinski-Harabasz, Davies-Bouldin и долю минимального кластера. Отклонить модель при доле < 0.05.
8. Перевести метрики в процентильные ранги полезности, инвертировать DB; `internal_score = .45*sil + .30*ch + .25*db_inverse`.
9. Для лучших кандидатов выполнить 100 повторных стратифицированных по ТИК подвыборок без возвращения по 80 %. На каждом повторе заново fit scaler и модель. ARI считать только на общих идентификаторах.
10. `total_score = .65*internal_score + .35*ari_percentile`. При разнице < 0.02 рекомендовать более простую модель.

Все параметры должны редактироваться в форме и попадать в паспорт запуска. Длительные операции выполняй Celery-задачей. Задача идемпотентна, имеет понятный прогресс и корректно обрабатывает повторный запуск.

- карточка проекта и участники;
- мастер импорта: файл → сопоставление → проверка → подтверждение;

На каждой визуализации укажи знаменатель, число использованных/исключённых строк и предупреждение, что кластеризация не устанавливает причин и нарушений.

## API и экспорт

Добавь JSON endpoints для статуса задачи и данных графиков; изменяющие endpoints защищены CSRF. Экспортируй назначения в CSV/XLSX, параметры и версии в JSON, сводный HTML/PDF-отчёт. Защити CSV от formula injection. Имена файлов формируй сервером.

## Безопасность и эксплуатация

Production settings: `DEBUG=False`, `ALLOWED_HOSTS`, trusted origins, HTTPS redirect, secure cookies, HSTS с поэтапным включением, CSP, лимит запросов на вход и загрузку. Секреты не логировать. Добавь health checks, structured JSON logs, correlation ID, обработчик 400/403/404/500. Подготовь команды backup/restore и retention policy. Контейнеры запускай не от root.

## Тесты и критерии готовности

- Unit-тесты всех формул, VIF-цикла, ранжирования и bootstrap-сравнения.
- Property-based тесты для балансов и диапазонов процентов.
- Интеграционные тесты импорта, транзакций, Celery eager mode, permissions и экспорта.
- E2E smoke test полного сценария.
- Покрытие `analytics_core` ≥ 90 %, общее ≥ 80 %.
- `ruff check`, `pytest`, `python manage.py check --deploy` проходят.
- Нужны fixtures: корректный CSV, XLSX, ошибки баланса, нулевые знаменатели, дубликаты, кириллические заголовки.
- README содержит Windows/Linux команды, Docker Compose, миграции, создание суперпользователя, запуск тестов и восстановление резервной копии.

## Definition of Done

Новый пользователь с ролью аналитика может создать проект, загрузить тестовый набор, исправить mapping, получить отчёт качества, запустить анализ, увидеть прогресс и кандидатов, выбрать модель, просмотреть профили и скачать назначения с паспортом. Viewer видит только опубликованное. Повтор запуска с теми же данными, конфигурацией и seed воспроизводит результат. История и старые версии не изменяются задним числом.
